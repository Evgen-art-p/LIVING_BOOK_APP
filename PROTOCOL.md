## Живая Книга: Протокол взаимодействия Студия ↔ Маяк ↔ Искорка

> **Версия:** 2.0

## 1. Философия

Три модуля, один контракт:

```
СТУДИЯ (производит)  →  МАЯК (хранит и раздаёт)  →  ИСКОРКА (показывает)
    18 агентов              FastAPI сервер              HTML/JS плеер
                                 ↕
                        КАБИНЕТ РОДИТЕЛЯ
                         (dashboard UI)
```

**Правило:** Каждый модуль доверяет данным от предыдущего. Если данных нет — работает с тем что есть. Если не может — показывает заглушку, но **никогда не падает**.

**Принцип «Пять + Пять = Сердце»:** ИИ-агенты — не инструменты, а творческие партнёры. Шестой палец — скрытое преимущество.

## 2. Единый Пакет (Book Package)

### 2.1 Структура на диске (v2.0)

```
books/
├── registry.json                  ← МАСТЕР-РЕЕСТР. Маяк читает первым.
│
├── {uid_folder}/                  ← Папка по uid (например: u_7912_4455_99)
│   ├── book.json                  ← ОБЯЗАТЕЛЬНО. Точка входа
│   ├── chapters/
│   │   └── {chapter_id}.json      ← По одному файлу на главу
│   ├── characters/
│   │   └── {character_id}.json    ← Персонажи (опционально)
│   ├── child_profile.json         ← Профиль ребёнка (опционально)
│   ├── biography.json             ← Историческая Память (The Legacy)
│   ├── ethics.json                ← Этический фильтр (опционально)
│   ├── config.json                ← Настройки LLM/TTS (опционально)
│   ├── basket.json                ← Корзинка Даров / Тьютор Линк
│   ├── gift_baskets/              ← Корзинки подарков (опционально)
│   │   └── basket_{id}.json
│   └── _master_brief.json         ← Служебный: бриф от SET (не для Искорки)
│
├── grondheim_01/                  ← Общая эталонная книга (без uid)
└── personal/                      ← Быстрые персональные сцены
```

### 2.2 Обратная совместимость (миграция v1 → v2)

Старые папки по имени (например `books/Женя/`) продолжают работать. Маяк при первом обращении к старой папке по имени:
1. Создаёт запись в `registry.json` с новым `uid`.
2. Не перемещает файлы — работает с папкой как есть.
3. Записывает `folder: "Женя"` в реестр.

Новые записи создаются исключительно с uid-папками.

```json
        "audio_file": "string — путь к аудио (опционально)",

          "ui_pulse_color": "string",
          "memory_vector": "string — тег для памяти",
          "memory_key": "string — ключ для биографии"
        },
        "fallback": {
          "reply_text": "string — ответ по умолчанию",
          "ui_pulse_color": "cyan"
        }
      },
      
      "choices": [
        {
          "id": "string",
          "label": "string — текст для UI",
          "keywords": ["слово1", "слово2"],
          "next_scene": "string — scene_id",
          "memory_vector": "string"
        }
      ],
      
      "context": "string — контекст для LLM (free_talk)",
      "ai_instructions": "string — правила для LLM",
      "max_turns": "number — макс ходов в free_talk",
      "on_end": "string | object — scene_id следующей | блок перехода | 'end'"
    }
  ]
}
```

### КРИТИЧЕСКОЕ ПРАВИЛО: `scene_id` vs `id`

```
ЗАКОН: Поле сцены называется "scene_id", НЕ "id"
```

- Спецификация: `scene_id`
- Искорка индексирует по: `scene_id`
- Если агент сгенерировал `id` вместо `scene_id` → A16 (Марка Файн) ОБЯЗАН исправить
- Fallback в Искорке: `const sid = s.scene_id || s.id` (защита от кривых данных)

## 5. API Маяка: контракт эндпоинтов (v2.0)

### 5.1 Искорка → Маяк (uid-маршрутизация)

| Метод | URL (v2 — приоритет) | URL (v1 — обратная совместимость) | Возвращает | Когда |
|-------|------|------|------------|-------|

| GET | `/api/beacon/uid/{uid}/chapters/{id}` | `/api/beacon/stories/{name}/chapters/{id}` | chapter JSON | При загрузке главы |
| GET | `/api/beacon/uid/{uid}/stories` | `/api/beacon/stories/{name}` | `[{story_id, title}]` | Проверка новых книг |
| POST | `/api/free_talk` | — | `{text, color, cached}` | Гибридный диалог |
| POST | `/beacon` | — | `{ok, received}` | Ночная синхронизация (NightBeacon) |

### 5.2 Кабинет Родителя → Маяк (uid-маршрутизация)

| Метод | URL (v2 — приоритет) | URL (v1 — обратная совместимость) | Возвращает | Когда |

| Метод | URL | Возвращает | Когда |

## 6. Правила отказоустойчивости Искорки

### 6.1 Книга не загрузилась

```
BookEngine.init() → catch → speak("Привет, {name}. Я здесь.") → idle
```
Кнопка ВСЕГДА работает. Если нет книги — Искорка просто здоровается.

### 6.2 Сцена не найдена

```
getScene(chId, sceneId) → null → getFirstScene(chId) → null → idle
```

### 6.3 Маяк недоступен

```
fetch(/api/free_talk) → catch → локальный fallback → "Я тебя слышу..."
```

### 6.4 Поле отсутствует

```
scene.intro_event → null/undefined → setState('idle') (не падаем)
scene.scripted_responses → {} → Dialog возвращает дефолт
scene.global_intents → {} → GlobalIntents не матчит ничего
```

### 6.5 Глава ещё не создана (Пылесос 2.0)

```
fetch(next_chapter) → 404 → speak("Эта страница ещё создаётся волшебством, загляни завтра!") → idle
```

## 10. Цифровой Паспорт (Fingerprint System)

Чтобы система работала годами и не зависела от смены имён или устройств, вводится **Master Registry**.

### 10.1 Файл Реестра: `books/registry.json`

Этот файл — единственный, кто знает всё. Маяк читает его первым.

```json
{
  "version": "1.0",
  "updated_at": "2026-04-06T12:00:00",
  "profiles": [
    {
      "uid": "LB-2026-04-05-0001",
      "alias": "Женя",
      "folder": "Женя",
      "age_group": "7-12",
      "created_at": "2026-04-05",
      "last_activity": "2026-04-06T15:40:00",
      "history_file": "biography.json",
      "device_ids": ["dev_abc123"],
      "status": "active"
    }
  ]
}
```

### 10.2 Правило «Сквозного ID»

- **Студия (A16):** При генерации новой главы Студия получает `uid` из MASTER BRIEF. Она обязана записать этот `uid` в метаданные главы (`book.json → uid`).
- **Искорка:** В URL передаётся ID: `index.html?uid=LB-2026-04-05-0001`. Fallback: если `uid` нет в URL — работает по старому `?child=Женя`.
- **Маяк:** Если пришёл запрос с `uid` — лезет в `registry.json`, находит `folder`, отдаёт данные из `books/{folder}/`. Имя `alias` используется только для приветствия внутри сказки.
- **Кабинет Родителя:** Все запросы идут через `uid`. При первом входе — Маяк создаёт профиль в реестре.

### 10.3 Функция `resolve_uid()` в Маяке

```python
def resolve_uid(uid: str) -> Path | None:
    """Находит папку ребёнка по uid из registry.json"""
    registry_path = BOOKS_DIR / "registry.json"
    if not registry_path.exists():
        return None
    registry = json.loads(registry_path.read_text(encoding="utf-8"))
    for profile in registry.get("profiles", []):
        if profile["uid"] == uid:
            return BOOKS_DIR / profile["folder"]
    return None
```

### 10.4 Генерация uid

Формат: `LB-{YYYY-MM-DD}-{NNNN}` где `NNNN` — автоинкремент внутри дня.

```python
def generate_uid() -> str:
    today = datetime.now().strftime("%Y-%m-%d")
    registry = load_registry()
    today_count = sum(1 for p in registry["profiles"] if p["uid"].startswith(f"LB-{today}"))
    return f"LB-{today}-{today_count + 1:04d}"
```

## 11. Бесшовные переходы (Deep Linking)

Чтобы Искорка не замолкала между главами, меняется логика завершения.

### 11.1 Финал Главы (`on_end` — расширенный формат)

В последней сцене главы Марка Файн (A16) обязан прописать переход:

```json
"on_end": {
  "action": "load_next_chapter",
  "target_chapter": "ch02",
  "auto_start": true
}
```

Допустимые значения `action`:
- `"load_next_chapter"` — загрузить следующую главу
- `"show_credits"` — показать финальный экран
- `"end"` — конец книги

Обратная совместимость: если `on_end` — строка (старый формат), Искорка трактует её как `scene_id`.

### 11.2 Логика Пылесоса 2.0

Если Искорка видит `on_end.action === "load_next_chapter"`:
1. Показывает анимацию «Искорка летит к следующей звезде».
2. Делает запрос к Маяку: `/api/beacon/uid/{uid}/chapters/{target_chapter}`.
3. Если файла нет (глава ещё пишется) — Искорка говорит: *«Эта страница ещё создаётся волшебством, загляни завтра!»*
4. Если файл есть — автоматически начинает первую сцену.

```
2. НОЧНАЯ СИНХРОНИЗАЦИЯ
   NightBeacon → POST /beacon (батч обезличенных событий)
   Маяк записывает в biography.json по uid
   
3. ЧТЕНИЕ СТУДИЕЙ
   Пайплайн → A00 Фабула Фейн читает biography.json
   Генерирует 50-ю главу, «помня» выбор из 1-й главы (3 года назад)
   
4. ЧТЕНИЕ КАБИНЕТОМ
   GET /api/parent/uid/{uid}/biography → Семантическое Зеркало
   Визуализация: облако тегов, советы от Софии
```

### 12.3 Правило записи

Маяк обновляет `biography.json` в двух случаях:
1. **После генерации:** A16 Марка Файн добавляет запись в `karmic_trail` с метаданными новой главы.
2. **После NightBeacon:** Маяк добавляет `choices_made` и `tags` из батча Искорки в соответствующую запись `karmic_trail`.

## 13. Кабинет Родителя (Узел Контрол)

### 13.1 Архитектура

Кабинет — это `dashboard/index.html`, раздаётся Маяком как статика. Общается с Маяком через API.

```
dashboard/index.html → API Маяка → books/{uid_folder}/
```

### 13.2 Компоненты интерфейса

| Компонент | Источник данных | API |
|-----------|----------------|-----|
| **Семантическое Зеркало** | `child_profile.json → psychological_patterns` | `GET /api/parent/uid/{uid}/profile` |
| **Мостик в Реал** | `basket.json → bridge_to_reality` | `GET /api/parent/uid/{uid}/basket` |
| **Тьютор Линк** | Форма → Пайплайн | `POST /api/studio/generate` |
| **Хроники Грондхейма** | `biography.json → karmic_trail` | `GET /api/parent/uid/{uid}/biography` |
| **Границы Мира** | Настройки (локальные) | — |
| **Статистика** | `child_profile.json` | `GET /api/parent/uid/{uid}/profile` |

### 13.3 Табы

- **📡 Эфир** — Статус подключения, Семантическое Зеркало, Тьютор Линк (заказ новой истории).
- **📜 Память** — Хроники Грондхейма (biography.json), облако персонажей.
- **📊 Статистика** — Профиль ребёнка: сессии, выборы, паттерны, зоны роста.

### 13.4 Принцип uid-маршрутизации в Кабинете

Кабинет при загрузке:
1. Запрашивает `GET /api/registry` — получает список всех детей.
2. Если ребёнок один — автоматически выбирает его uid.
3. Если несколько — показывает селектор.
4. Все последующие запросы идут через `uid`.

Fallback: если `registry.json` не существует — Кабинет работает по старой логике (`CHILD_NAME = 'Женя'`).

### 13.5 Визуальный стиль (v2.0)

- Шрифт: **Nunito** (тёплый, округлый, дружелюбный).
- Палитра: `slate-50` фон, `indigo-600` акцент, `emerald` для статуса, `amber` для советов.
- Карточки: `rounded-[2rem]`, `shadow-sm`, `border-slate-100`.
- Анимации: Искорка-орб (pulsing), Хронос-индикатор (ping).
- Вёрстка: Tailwind CSS через CDN.
- Принцип: чисто, легко, без перегрузки. Как детская книга, но для взрослого.

## 14. Критические правила архитектуры (для ИИ-ассистентов)

1. **Primary Channel — Звук:** Никаких текстовых полей ввода для ребёнка. Главный интерфейс — голос (STT) и 3D-звук (TTS/Foley).
2. **Визуал вторичен (Принцип Тёмной Комнаты):** Экран почти всегда чёрный. На нём отображается только пульсирующая Искорка (статус-орб).
3. **Zero Data (Автономный Форт):** Все диалоги и выборы ребёнка обрабатываются и хранятся локально (IndexedDB). На сервер — только обезличенные мета-данные раз в сутки.
4. **Гибридный Мозг (Hybrid Intent Engine):** Локальный keyword-матчинг (бесплатно) → при промахе LLM через Маяк (с кэшем).
5. **Матрица Эмпатии (Метод Гиппенрейтер):** ИИ никогда не даёт готовых решений, только терапевтические направляющие вопросы.
6. **Одно касание — навсегда голос:** После первого тапа «Зажечь Искорку» — `autoListen = true`. STT автоматически перезапускается.
7. **Имя ребёнка священно:** Используется только для приветствия и сюжета. Под капотом — `uid`.
